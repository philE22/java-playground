## 인기 게시글 조회수 문제

### 상황

대규모 커뮤니티 서비스에서 인기 게시글 하나에 트래픽이 집중되는 상황입니다.

게시글 상세 조회는 평소에는 많지 않지만, 인기 게시글이나 이벤트성 게시글의 경우 짧은 시간 동안 수천~수만 건의 조회 요청이 몰릴 수 있습니다.

조회수는 사용자에게 거의 실시간으로 보여줘야 하지만, 결제 금액이나 재고처럼 항상 정확한 최신 값이 필요한 데이터는 아닙니다. 수 초~수 분 정도 DB 반영이 늦어져도 서비스적으로 문제가 없습니다.

만약 사용자가 게시글을 조회할 때마다 RDB의 view_count를 직접 증가시키면, 동일한 게시글 row에 UPDATE 요청이 집중되어 DB 부하가 커질 수 있습니다.

따라서 조회 요청에서는 Redis에 조회 증가량을 빠르게 기록하고, 일정 주기마다 누적된 값을 DB에 반영하려고 합니다.

### 조회수 요구사항
- 게시글이 조회될 때마다 조회수를 1 증가시킨다.
- 동일한 게시글에 동시에 많은 조회 요청이 발생할 수 있다.
- 여러 애플리케이션 서버에서 동시에 조회수를 증가시켜도 값이 유실되면 안 된다.
- 조회 요청마다 RDB에 UPDATE를 수행하지 않는다.
- 조회수 증가 요청은 가능한 빠르게 처리해야 한다.
- Redis에 일정 기간 조회수를 누적할 수 있어야 한다.
- 누적된 조회수는 일정 주기마다 RDB에 반영한다.
- RDB에 반영되기 전이라도 사용자에게 최신에 가까운 조회수를 보여줄 수 있어야 한다.
- Redis → DB 동기화 과정에서 장애가 발생했을 때 조회수가 중복 반영되거나 유실되는 문제를 고려해야 한다.
- Redis 장애 시 조회수 증가 요청을 어떻게 처리할지 정책을 정해야 한다.
- 조회수는 약간의 오차나 반영 지연을 허용할 수 있다.
